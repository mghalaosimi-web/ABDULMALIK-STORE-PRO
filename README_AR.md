## تعريف المنتج

ABDULMALIK ERP نظام مكتبي لإدارة العمليات اليومية لمتجر بيع وصيانة الهواتف، ويجمع بين استقبال أجهزة الصيانة ومتابعة مراحلها، ونقطة البيع، والمخزون العام، وقسم مستقل للأكسسوارات، والهواتف المسجلة بالـ IMEI، والمشتريات، والعملاء، والخزنة، والخدمات، والتقارير، والمستخدمين والصلاحيات، وسجل التدقيق، والنسخ الاحتياطي والاستعادة.

يعمل كمبيوتر Windows بوصفه المضيف المحلي. تُحفظ البيانات التشغيلية في SQLite، وتوفر الخدمة المحلية واجهة HTTP للأجهزة الموجودة على شبكة المحل. صُممت الوظائف الأساسية لإصدار Windows كي تعمل دون الحاجة إلى اتصال دائم بالإنترنت.

## نطاق الإصدار الحالي

- **الإصدار المستهدف:** Windows x64 مع مثبت Inno Setup.
- **Android:** ملفات المصدر وسير عمل بناء تجريبي يدوي موجودة، لكن التطبيق غير معتمد كإصدار إنتاجي في هذه المرحلة.
- **السحابة:** كود Firebase/Firestore وقواعده محفوظة كقاعدة تطوير مستقبلية. المزامنة معطلة افتراضياً، وإعداد Firebase فارغ، والتتبع العام للعملاء معطل.
- **نظام التفعيل داخل التطبيق:** لا يفرض هذا الإصدار كود تفعيل أو اشتراكاً أو انتهاء تجربة أو حداً للأجهزة. هذا لا يمنح بحد ذاته حقوق النشر أو إعادة التوزيع أو الترخيص الفرعي؛ راجع `LICENSE_STATUS.md`.
- **الأمان:** اتصال الشبكة المحلية وبعض جوانب التشفير تحتاج إلى مراجعة أمنية إضافية قبل الاستخدام عبر شبكات غير موثوقة.

نجاح البناء لا يعني وحده أن النظام آمن للإنتاج. راجع [سياسة الأمان](SECURITY.md) والدراسة التقنية قبل إدخال بيانات عملاء حقيقية.

## بناء نسخة Windows

المتطلبات على جهاز بناء Windows 10/11 x64:

- Flutter stable SDK متوافق مع قيد Dart في `source/pubspec.yaml`.
- Visual Studio 2022 Build Tools مع **Desktop development with C++**.
- Inno Setup 6.

من PowerShell:

```powershell
cd source
flutter doctor -v
powershell -ExecutionPolicy Bypass -File .\tool\build_release.ps1
```

يستعيد السكربت الاعتماديات، وينفذ التحليل والاختبارات، ويبني نسخة Windows x64، ثم ينشئ المثبت `builds/ABDULMALIK-ERP-Setup-<version>.exe`. كما ينفذ GitHub Actions التحقق واختبار تثبيت وإزالة صامتين على Windows runner.

## احتياطات التشغيل والبيانات

1. اختبر النسخ الاحتياطي والاستعادة على قاعدة بيانات تجريبية قبل التشغيل الفعلي.
2. ضع جهاز Windows المضيف داخل شبكة محلية موثوقة ومقيدة الصلاحيات.
3. لا تعرض خدمة HTTP المحلية مباشرة على الإنترنت العام.
4. لا تفعّل Firebase قبل إنشاء مشروع مستقل ومراجعة قواعد الأمان والخصوصية والاعتمادات.
5. لا ترفع مفاتيح التوقيع أو المفاتيح الخاصة أو ملفات `key.properties` أو keystores أو `.env` إلى Git.
